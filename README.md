# sink

영화 대본과 영상을 주면 영상 기준 대본(`final.json`)을 만든다. 영상에서 실제로 들린 말에 시각을 붙이고, 대본에서 화자·씬·지문을 가져와 시간 순서로 늘어놓은 파일이다. 대본과 다르게 말한 곳, 대본에 없는 말, 영상에 없는 대본 대사를 따로 표시한다.

- 결과 파일에 무엇이 들어가는지: [FINAL_JSON.md](FINAL_JSON.md)
- 왜, 어떻게 만들었는지: [OVERVIEW.md](OVERVIEW.md)
- 모듈 사이 약속: [DESIGN.md](DESIGN.md), 수치: [REPORT.md](REPORT.md)

## 1. 한 줄 사용법

```
sink-film.cmd "C:\경로\써니.hwp" "C:\경로\써니.mkv"
```

대본과 영상을 한 쌍으로 준다. 순서는 상관없다. PowerShell 에서는 `.\sink-film.cmd ...` 로 친다(4절).

영상 등록, 받아쓰기, 대본과 맞추기, 최종본, 검사, 미리보기 자막까지 한 번에 돈다. 끝나면 `films\{film_id}\` 에 결과가 생기고, 마지막에 수치와 파일 전체 경로가 찍힌다.

| 파일 | 내용 |
|---|---|
| `final.json` | 영상 기준 대본. 이것이 결과물이다 |
| `preview.srt` | 눈으로 확인하는 자막 |
| `work\asr.json` | 받아쓰기 결과 |
| `work\align.json` | 대본 줄과 받아쓰기 낱말을 맞춘 기록 |

- film_id 는 영화 번호이고 `catalog.csv` 의 `film_id` 칸이다(써니 `local_0556`, 추격자 `local_0270`). 대본 문서 번호인 doc_id(`fm...`)와 다르다.
- 2시간짜리 영화가 GPU(RTX 12GB)에서 받아쓰기 13분쯤, 나머지 몇 분이다.
- 끝 요약의 `확인 필요 N건` 은 실패가 아니다. 사람이 들어 볼 만한 줄의 수다.
- 영상 등록은 `catalog.csv` 에 그 영화의 영상을 적고, 영상을 `videos\` 에 하드링크하는 일이다(다른 드라이브면 복사). `catalog.csv` 는 git 에 들어 있는 파일이라 실행 뒤 바뀐 것으로 나온다.

## 2. 준비물

| 무엇 | 왜 |
|---|---|
| Windows, Python 3.11 이상 | |
| ffmpeg, ffprobe (PATH 에) | 영상에서 소리를 꺼낸다 |
| NVIDIA 그래픽 카드, 여유 VRAM 5GB 이상 | 받아쓰기. GPU 를 못 쓰면 시작하지 않고 멈춘다. `--device cpu` 를 붙이면 CPU 로 돌고 2시간 영화에 3시간 넘게 걸린다 |
| 통일된 대본 폴더 `docs\` | 3절 참고. 저장소에 없다 |
| Claude Code 의 `claude` 명령(구독 계정으로 로그인) | 선택. 맞추기에서 애매한 줄을 물어본다. 없으면 캐시에 있는 답만 쓰고 끝까지 간다. 아예 부르지 않으려면 `--no-llm` |

## 3. 설치

이 폴더(`sink`)에서 한다.

```
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[asr,asr-gpu]"
.venv\Scripts\python -I tools\llm_cache_zip.py unpack
```

- `.venv` 는 꼭 이 폴더 안에 만든다. `sink-film.cmd` 가 옆의 `.venv` 를 찾는다.
- 받아쓰기 모델(large-v3-turbo, large-v3)은 처음 돌릴 때 저절로 내려받는다. 몇 GB 다.
- 받아쓰기 결과는 도구 판에 달려 있어 faster-whisper 1.2.1, ctranslate2 4.8.3 으로 고정해 두었다. 판이 다르면 같은 영상도 결과가 달라진다.
- 셋째 줄은 저장소에 묶어 둔 LLM 응답 캐시를 푼다. claude 를 다시 부르지 않고 같은 결과를 얻기 위한 것이다.

**대본 자료 넣기.** 저장소에는 코드와 대본 목록(`catalog.csv`)만 있다. 대본 글은 저작권 때문에 넣지 않았다. 그래서 형식을 통일해 둔 대본 폴더 `docs\`(684문서, 약 750MB)를 저장소 관리자(jonghyun02)에게 받아 이 폴더 안에 `docs\` 로 넣어야 한다. 한 영화만 돌릴 거면 그 영화의 대표 대본 폴더 하나(써니는 `docs\fm847721\`)만 있어도 된다.

원본 대본 묶음(`filmmakers_scripts\`)에서 직접 만들 수도 있다. 이 묶음도 저장소에 없어 관리자에게 받는다. 한컴오피스 한글과 반디집(`C:\Program Files\Bandizip\bz.exe`)이 깔려 있어야 하고 `.venv\Scripts\python -I -m sinkprep all` 로 돈다. 새로 받은 저장소에서는 끝의 검사가 `films/local_0270/final.json 이 없음` 으로 실패해 종료 코드 1이 나지만 `docs\` 는 만들어진다.

## 4. 실행

### 대본을 가리키는 세 가지 방법

```
sink-film.cmd "C:\경로\써니.hwp" "C:\경로\써니.mkv"
sink-film.cmd 써니 "C:\경로\써니.mkv"
sink-film.cmd fm847721 "C:\경로\써니.mkv"
```

- **대본 파일**: 파일 내용(sha1)으로 `catalog.csv` 에서 문서를 찾는다. 통일해 둔 684문서에 있는 파일이어야 한다.
- **제목**: `catalog.csv` 의 `title_norm` 칸과 같은 제목. 띄어쓰기, 문장부호, 대소문자는 보지 않는다. 일부만 같은 제목은 찾지 않는다.
- **doc_id**: `catalog.csv` 의 `doc_id` 칸.

어느 방법이든 쓰는 대본 글은 `docs\{doc_id}\script.json` 이다. 대본 파일은 어느 문서인지 찾는 데만 쓴다. 원본 대본 파일이 없으면 제목이나 doc_id 로 준다.

- 같은 영화의 문서가 여럿이면 대표 대본(`catalog.csv` 의 `is_primary` 가 true 인 문서)으로 돈다.
- 대표 대본이 한국어이고 번역이 아닌 영화만 돈다. 684문서 638편 가운데 368편이다.
- 684문서에 없는 새 대본은 아직 넣을 수 없다.

### 치는 법

- `sink-film.cmd` 는 배치 파일이다. 앞에 `python` 을 붙이지 않는다.
- PowerShell 에서 이 폴더 안이면 `.\sink-film.cmd ...`
- 다른 폴더에서는 전체 경로로 친다: `C:\...\sink\sink-film.cmd ...`
- PowerShell 에서 `sink-film.cmd` 의 경로를 큰따옴표로 감쌀 때는 앞에 `&` 를 붙인다: `& "C:\내 폴더\sink\sink-film.cmd" 써니 "C:\경로\써니.mkv"`
- 공백이 있는 경로와 제목은 큰따옴표로 감싼다. 제목은 붙여 써도 찾는다.

### 옵션

| 옵션 | 뜻 |
|---|---|
| `--no-llm` | claude 를 부르지 않는다 |
| `--device cpu` | GPU 없이 CPU 로 받아쓴다. 2시간 영화에 3시간 넘게 걸린다 |
| `--no-rescue` | 놓친 대사 되찾기 받아쓰기를 뺀다. 빨라지지만 조용한 대사를 놓친다 |
| `--force` | 그 영화에 이미 다른 영상이 등록돼 있을 때 이 영상으로 바꾼다 |
| `--open` | 끝나면 결과 폴더를 연다 |

중간에 끊기면 같은 명령을 다시 친다. 끝난 단계는 건너뛴다.

## 5. 결과 보기

영상 플레이어(팟플레이어, VLC)에서 영상을 열고 `films\{film_id}\preview.srt` 를 자막으로 불러온다.

| 자막 모양 | 뜻 |
|---|---|
| `이름: 글` | 들린 대사. 글은 들린 그대로다 |
| `이름?: 글` | 화자가 추정인 대사 |
| `[+] 글` | 대본에 없는데 들린 말 |
| `[없음] 이름: 대본 글` | 대본에 있는데 영상에서 못 찾은 대사 |

`final.json` 을 프로그램으로 읽는 법은 [FINAL_JSON.md](FINAL_JSON.md) 9절에 있다.

## 6. 자주 막히는 곳

| 증상 | 까닭과 방법 |
|---|---|
| `python sink-film.cmd ...` 가 문법 오류를 낸다 | 배치 파일을 파이썬으로 읽어서다. `python` 을 빼고 친다 |
| PowerShell 이 `sink-film.cmd` 를 찾지 못한다 | 앞에 `.\` 를 붙인다 |
| `.venv\Scripts\python.exe not found` | 설치를 안 했거나 `.venv` 가 이 폴더 밖에 있다. 3절 |
| `docs/.../script.json 이 없다` | 대본 자료를 안 넣었다. 3절 |
| `대본 파일 ... 은 catalog 에 없다` | 그 파일이 684문서에 없다. 제목이나 doc_id 로 준다 |
| `대본 파일 ... 은 통일해 둔 대본과 내용이 다르다` | 같은 제목의 다른 판 파일이다. 찍힌 doc_id 로 준다. 이때 쓰는 대본은 준 파일이 아니라 통일해 둔 판이다 |
| `제목이 ... 인 대본이 catalog 에 없다` | `title_norm` 칸과 제목이 다르다. 대본 파일이나 doc_id 로 준다 |
| `제목이 ... 인 대본이 N개다` | 같은 제목의 문서가 여럿이다. 찍힌 목록의 doc_id 하나를 준다. 같은 영화의 문서면 어느 것을 줘도 대표 대본으로 돈다 |
| `... 는 대본 언어 en이다` | 대표 대본이 한국어가 아니거나 번역 대본인 영화다. 지금은 돌릴 수 없다 |
| `받아쓰기를 GPU 로 할 수 없어 시작하지 않는다` | 찍힌 까닭을 본다. 다른 프로그램이 GPU 를 쓰는 중이면 끄고 다시 친다. `CUDA 라이브러리를 찾을 수 없다` 면 3절의 설치 줄을 다시 돌린다. `CUDA 장치를 찾지 못했다` 나 `nvidia-smi 가 없어` 면 NVIDIA 드라이버를 깐다. 그래도 안 되면 `--device cpu` |
| `... 에는 다른 영상이 이미 등록돼 있다` | `catalog.csv` 에 그 영화의 다른 영상 파일이 적혀 있다. 추격자와 써니는 관리자 PC 의 영상으로 등록된 채 저장소에 들어 있어서, 가진 영상 파일이 그것과 다르면 처음 돌릴 때도 이 알림이 난다. `--force` 를 붙이면 이 영상으로 바꾸고 받아쓰기부터 새로 한다 |
| final 단계에서 멈추고 `번역 단계가 없어 final.json 을 만들지 않음` 이 찍힌다 | 외국어로 들린 대사가 한 줄이라도 있는 영화다. 번역 단계가 없어서 지금은 외국어 대사가 없는 한국어 영화만 끝까지 간다 |

## 7. 지금 상태와 한계

- 끝까지 돌린 영화는 둘이다. 추격자(일치율 0.613), 써니(일치율 0.565).
- 사람이 소리를 듣고 만든 정답과 견준 적은 없다. 결과를 쓰기 전에 [FINAL_JSON.md](FINAL_JSON.md) 10절을 읽는다.
- 외국어 대사가 없는 한국어 영화만 된다.
- 통일해 둔 684문서에 없는 대본은 넣을 수 없다.
- 새로 받은 사본에 설치하고 써니를 돌려 원래 결과와 바이트까지 같은 것을 확인했다(2026-11-15). 그 시험에서 ctranslate2 판 고정이 빠진 것을 찾아 고쳤다. 받아쓰기 캐시를 옮겨 놓고 한 시험이라, 다른 PC 에서 받아쓰기부터 새로 해 본 적은 없다.
- 단계를 하나씩 돌리는 법, 등록을 지우는 법, 받아쓰기 장치에 대한 자세한 내용은 [OVERVIEW.md](OVERVIEW.md) 2.2절에 있다.
